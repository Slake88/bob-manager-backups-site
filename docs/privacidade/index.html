2. Finalidade e estado da aplicação

A finalidade da BOB Manager Backups é apoiar cópias de segurança internas do BOB Manager para o Google Drive, exclusivamente no contexto dos Blue On Black.

No ramo de código consultado existe um script de pré-verificação Google Drive. O script espera receber o identificador do cliente OAuth, o segredo do cliente e um refresh token por variáveis de ambiente designadas para GitHub Actions; troca o refresh token por um access token, consulta metadados de uma pasta com nome definido no código e cria uma pasta vazia se não a encontrar. A consulta solicita os campos id, nome e tipo MIME.

Este script não lê conteúdos de ficheiros, não envia nem descarrega backups e não executa uma recuperação. Não foi encontrado, nos workflows do ramo consultado, um workflow que invoque este script. A sua execução e a configuração efetiva dos segredos não foram confirmadas.

Por confirmar antes da versão definitiva: categorias de dados pessoais e técnicos que serão incluídas em futuros backups, pessoas abrangidas, dados de conta recebidos da Google, registos técnicos e fundamento aplicável. Não se presume o conteúdo dos backups.

3. Autorização Google Drive

O âmbito esperado pelo script de pré-verificação é https://www.googleapis.com/auth/drive.file. Este âmbito permite criar ficheiros e aceder aos ficheiros criados pela aplicação ou que o utilizador abriu ou partilhou com ela. Conforme a operação e o ficheiro, pode permitir consulta, alteração e eliminação; não equivale a acesso geral a todo o Drive. A documentação da Google descreve o âmbito e o respetivo acesso.

O script verifica se a resposta de token inclui drive.file quando a resposta apresenta o campo scope. Não comprova que esse seja o único âmbito concedido, nem falha se o campo estiver ausente. A configuração OAuth, o pedido real de autorização e os âmbitos efetivamente concedidos têm de ser confirmados antes de produção. Não se afirma que não existam outros âmbitos.

A autorização Google é separada da autenticação e das permissões do BOB Manager.

4. Google Drive, acessos e destinatários

Na pré-verificação descrita, são trocados tokens com a Google e consultados metadados da pasta própria. Se a pasta não existir no âmbito acessível, o script cria-a. O código não transfere conteúdo de backups nesta operação.

Por confirmar antes de ativar cópias: conta e localização efetiva do Drive, estrutura de pastas, pessoas com acesso, partilhas, prestadores, transferências internacionais e salvaguardas. O código espera obter credenciais a partir de GitHub Actions secrets, mas não confirma que estejam configuradas nem descreve a política real de acesso, rotação ou retenção desses segredos e registos.

5. Cifragem, retenção e eliminação

Não foram validadas operacionalmente a cifragem dos backups, a periodicidade, a retenção, a rotação, a eliminação de ficheiros ou versões, nem a recuperação. Não se promete que uma cópia exista, esteja cifrada ou possa ser restaurada.

Revogar o acesso Google pode impedir futuras chamadas à API. A revogação, por si só, não elimina ficheiros ou dados anteriormente guardados no Drive.

7. Este site

Esta versão é composta por páginas estáticas com CSS local; não contém formulários, autenticação, JavaScript, ferramentas de análise ou cookies definidos pelo código do site. O site não recebe backups nem tokens OAuth.

O alojamento está previsto no GitHub Pages. O fornecedor pode tratar dados técnicos dos pedidos de acesso segundo a sua declaração de privacidade. Por isso, não se afirma que uma visita ao site não envolva qualquer tratamento.
